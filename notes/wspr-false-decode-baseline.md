# WSPR 偽デコード — 変更前ベースラインと 0.9.1 の結果

> 測定日: 2026-08-11 / 対象: `webft8` main `8fdab2e`
> 依存: `mfsk-core` git rev `47f0e63`（`Cargo.toml` の pin）
> 目的: mfsk-core 側の「OSD は Fano を通ったデータでのみ hash を使う」変更の A/B 基準

## なぜ今測ったか

受理条件を締める変更は、常に**誤警報と再現率のトレードオフ**になる。そして再現率の劣化は
静かに起きる —— 誤警報は目に付くが、取りこぼしは何も表示されないので気づけない。
変更が入った後では「変更前がどうだったか」を再現できないため、先に押さえた。

## 測定条件

- 計測対象は **アプリが実際に読む WASM**（`decode_wspr_wav_f32`）。mfsk-core を直接叩いていない
- 信号: `JL1NIE PM95 37` @ 1500 Hz（4 トーンの中心）、スロット開始 1.0 s
- 雑音: σ=1/sample、SNR は WSJT-X 規約（2500 Hz 基準帯域）。ft8-bench のシミュレータと同一規約
- シード固定。**シードを変えると下記の数値と比較できない**

再実行:

```bash
node notes/wspr-decode-baseline.mjs                      # docs/ の配信ビルドに対して
WSPR_PKG_DIR=ft8-web/pkg node notes/wspr-decode-baseline.mjs   # 新規ビルドに対して
```

## 所見

**観測された偽デコードは一件残らず Type-2（prefix/callsign 形式）だった。**
`W9J/I22GIS` / `A5Y/ID6MVV` / `U6S/JL0LRT` —— 素の Type-1 は皆無。
ハッシュ済みコールサイン経路そのものなので、上流の修正方針と症状が一致している。

**偽デコードの中身は安定しない。** 同じ 1626.5 Hz で、126 Hz 離れた場所に信号を足すだけで
`W9J/I22GIS 30` → `A5Y/ID6MVV 7` と丸ごと入れ替わる。WSPR には FT8 の CRC-14 に相当する
独立検証が無く、FEC が収束した先が何であれ通ってしまう。外から見た「CRC が無い」とは
こういう挙動を指す。

**駆動源は 2 クラスある。**

1. **雑音由来** — 1626.5 Hz のものは信号の有無に関わらず出る。特定の雑音実現が
   受理条件を満たしてしまうケース。頻度は低いが再現性がある
2. **信号由来** — -30 dB で本物のデコードが崩れる時に出た `U6S/JL0LRT 3` @1500 Hz。
   信号周波数そのもので、`JL1NIE` の破損版に見える。本物を掴んだ上で誤った符号語に
   収束したケース

なお当初「信号がある時だけ偽デコードが出る」と判断したが、同一シードでの ON/OFF 比較で
**誤りと判明**した。§1 と §3 でシード帯が違ったための錯覚。ON/OFF を同一シードで
並べるまで切り分けられなかったので、A/B の際も §3 は必ず一緒に見ること。

## 結果 — mfsk-core 0.9.1（2026-08-11 測定）

`bfab491`（OSD を Fano 確認済みコールサインに限定）＋ issue #275 の wsprd 移植 6 コミット。

| 注入 SNR | 本物 47f0e63 → 0.9.1 | 偽 47f0e63 → 0.9.1 |
|---:|---|---|
| -18 dB | 8/8 → 8/8 | 4 → 1 |
| -22 dB | 8/8 → 8/8 | 2 → 1 |
| -26 dB | 8/8 → 8/8 | 2 → 1 |
| **-28 dB** | **7/8 → 8/8** | 3 → 1 |
| **-30 dB** | **1/8 → 7/8** | 5 → 0 |
| 合計（偽） | | **16 → 4** |

ノイズのみは前後とも 0/20。

**再現率を一切犠牲にせず偽デコードが 1/4 になった。** 受理条件を締める変更としては
異例だが、これは #275 の「~2 dB の AWGN ギャップ解消」が同梱されているため。
締める変更と広げる変更が同時に入ったので、`bfab491` 単体の代償は
この測定からは分離できない。

### 残った 1 件

4 件の偽デコードは全て**同一のもの**（seed 7、各 SNR で 1 回ずつ）:

```
"<#0640e> CBS9WR 59" @1644.29 Hz  dt 0.00
```

性質が修正前と入れ替わっている:

| | 修正前（1626.5 Hz） | 0.9.1（1644.3 Hz） |
|---|---|---|
| 駆動源 | **雑音由来**（信号なしでも出る） | **信号由来**（信号なしでは出ない） |
| 表示 | `A5Y/ID6MVV 7` — 実在しそうな複合コール | `<#0640e> …` — 未解決ハッシュとして可視 |

つまり `bfab491` は雑音由来クラスを潰し、かつ**偽物が偽物に見えるようになった**
（捏造されたコールサインではなく未解決ハッシュとして表示される）。運用上はこの差が大きい。

残存分について上流に渡せる材料:

- 信号 ON でのみ出現、信号から 144 Hz 離れた位置、-18〜-28 dB で不変。
  WSPR は SIC を行う（`546c1a9` / `2da820e`）ので、**本物を減算した残差**が
  候補を生んでいる可能性がある
- `CBS9WR` は Maidenhead として不正（3〜4 文字目は数字でなければならない）。
  グリッドの妥当性チェックだけでこの 1 件は落とせるはず
